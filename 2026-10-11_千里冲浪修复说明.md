## 2026-10-11 — Fix: freeze after beating Norman (5th gym) on MyBoy  [IMPLEMENTED + TESTED headless]

Symptom (user, MyBoy on phone): right after the Norman battle the game froze; Wally's dad never walked in, so HM Surf was never given.

Investigation:
- The user's in-game save (outside Petalburg Gym, 4 badges) was run on the delivered ROM (SHA1 21268e6d…) in headless mGBA, and the real battle against Norman was played. The whole sequence worked: badge, Facade, dad arrives, city, Wally's house, Surf.
- The user's MyBoy mid-battle save state, loaded into mGBA, also played through to Surf.
- The user's MyBoy "stuck" save state showed the script at `WallysDadArrives+7` (right after `applymovement`). The CPU had applymovement's registers (r5 = localId 11, r8 = movement pointer), but its PC was inside `ScrCmd_lock` at 0x0A22AFFE, the ROM mirror. That is a wild jump into the middle of a loop, with a garbage counter, so it never ends.
- Root cause (most likely): pokeemerald-expansion tags "effect-instrumented" script commands, specials and callnatives by storing their addresses in ROM mirror 1 (`+ROM_SIZE`, i.e. 0x0A000000), and the engine *executed* them from that mirror. MyBoy mis-executes code that runs from the mirror. This was not reproducible in mGBA.

Change:
- `include/script.h`: added `SCRIPT_UNTAG_FUNC(f)`, which maps a 0x0A…/0x0B… pointer back to 0x08…/0x09…. Other pointers are unchanged.
- `src/script.c`: `RunScriptCommand` and the effect-analysis loop call `SCRIPT_UNTAG_FUNC(*func)`. The analysis still uses the tagged pointer for detection.
- `src/scrcmd.c`: `special`, `specialvar`, `callnative` and `gotonative` call through the untagged address.
- `data/maps/PetalburgCity/scripts.inc` (recovery): on entering the city, if FLAG_BADGE05_GET is set, FLAG_RECEIVED_HM_SURF is not set and VAR_PETALBURG_CITY_STATE == 3, the var is set to 6. A new OnFrame handler (state 6, `PetalburgCity_EventScript_SurfRecovery`) clears FLAG_HIDE_PETALBURG_CITY_WALLYS_DAD, sets state 4 and warps to (15,8), so the normal walk to Wally's house and the Surf gift play.

Tests (release build, SHA1 3dfdf6162248f0a76532f5bf533a8c4d77d792ee):
- From the user's .sav: real battle with Norman, then the full scene, then Surf received.
- Recovery: badge 5 set and city state 3, then enter Petalburg, then the walk to Wally's house plays and Surf is received.
- Random walk/talk soak (8 maps, including Lilycove Seaside Avenue): no freeze.

Delivery: rom_fix/r_aa + r_ab (merge with `copy /b r_aa + r_ab EmeraldStory.gba`). The port package is port7.tgz; check base_sha1.txt before overwriting.
